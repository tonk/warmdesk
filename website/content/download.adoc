[#server]
== Server

The server is a single statically-linked Go binary with the web UI embedded.
SQLite is bundled; PostgreSQL or MySQL are optional.
You run it on a machine or VM you control and reach it through your browser — there is no separate “cloud” SaaS installer.

Official CI builds publish **Linux x86-64** and **Linux ARM64** tarballs for each `{warmdesk-version}` tag on the {url-releases-latest}[latest release »].
Pick your architecture below (`latest/download` always resolves to files for the newest tag):

[cols="1,3", options="header"]
|===
|Platform |Download (latest)

|Linux amd64 (x86-64)
|link:{url-download-latest}/warmdesk-{warmdesk-version}-linux-amd64.tar.gz[`.tar.gz`], companion link:{url-download-latest}/warmdesk-{warmdesk-version}-linux-amd64.tar.gz.asc[GPG `.asc`] if published

|Linux ARM64 (aarch64)
|link:{url-download-latest}/warmdesk-{warmdesk-version}-linux-arm64.tar.gz[`.tar.gz`], companion link:{url-download-latest}/warmdesk-{warmdesk-version}-linux-arm64.tar.gz.asc[GPG `.asc`] if published
|===

Unpack the tarball, copy `warmdesk.yaml.example` to `warmdesk.yaml`, set `jwt_secret` to a safe value (the server rejects the demo default), and run `./warmdesk`.
TLS, systemd, and reverse proxies are covered in link:../docs/install/[Installation guide].
macOS or Windows hosts: build from source — see link:../docs/install/#_build_from_source[Build from source] in Installation — release tarballs are Linux-only.

[#desktop-client]
== Desktop client

WarmDesk ships **link:../docs/install/#desktop-apps[Tauri]** desktop builds for Linux, macOS, and Windows.
The desktop app is **only the client**: it wraps the same web UI as the browser and connects to **your** WarmDesk server URL (configured on first launch).
The server binary is never bundled inside the desktop package.

Pre-built installers are uploaded to the {url-releases-latest}[latest release »].
Click an asset below to download the current `{warmdesk-version}` build (URLs use GitHub’s `latest/download` redirects):

[#timer]
== Command-line timer

`warmdesk-timer` starts and stops time tracking from a terminal: `warmdesk-timer start Website` when you begin, `warmdesk-timer stop` when you're done, and the time is booked on your WarmDesk server.
The Linux `.deb` and `.rpm` desktop packages above already install it as `/usr/bin/warmdesk-timer`, and it is part of the server tarballs.
For other machines it is a single file with nothing to install:

[cols="1,3", options="header"]
|===
|Platform |Download (latest)

|Linux
|link:{url-download-latest}/warmdesk-timer-{warmdesk-version}-linux-amd64[amd64], link:{url-download-latest}/warmdesk-timer-{warmdesk-version}-linux-arm64[arm64]

|macOS
|link:{url-download-latest}/warmdesk-timer-{warmdesk-version}-darwin-arm64[Apple Silicon], link:{url-download-latest}/warmdesk-timer-{warmdesk-version}-darwin-amd64[Intel]

|Windows
|link:{url-download-latest}/warmdesk-timer-{warmdesk-version}-windows-amd64.exe[x64 `.exe`], link:{url-download-latest}/warmdesk-timer-{warmdesk-version}-windows-arm64.exe[ARM64 `.exe`]
|===

On Linux and macOS, make the file executable (`chmod +x`) and put it on your `PATH` as `warmdesk-timer`.
Setting it up takes a personal API key; see link:../docs/user-guide/#_timer_from_the_command_line[Timer from the command line] in the User Guide.

Most release files ship with a matching `.asc` detached GPG signature.
See link:../docs/install/#desktop-apps[Installation — Desktop apps] and the link:../blog/gpg-signed-releases/[GPG-signed releases] blog post for verifying downloads.
